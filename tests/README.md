# 테스트

```bash
node tests/run-all.js        # 전체 (약 2초, 의존성 설치 불필요)
node tests/columns.test.js   # 개별 실행도 가능
node tests/profile-save.js   # 저장 경로 성능 측정(테스트 아님)
```

`npm install` 없이 순수 node로 돌아간다. 프레임워크를 쓰지 않는 이유는 이 저장소에 빌드 단계가
없기 때문 — 도구를 하나 들이는 순간 "검증하는 코드"와 "배포되는 코드"가 갈라질 여지가 생긴다.

## 어떻게 검증하나

이 프로젝트에는 서버(Apps Script)도 프론트도 모듈 시스템이 없다. 프론트 본체는 `src/` 아래의
일반 스크립트 파일들이고(전역 공유), `index.html`의 `<script src>` 순서가 곧 실행 순서다.
그래서 테스트용으로 코드를 따로 조립하는 대신, **배포되는 파일을 그대로 실행한다**:

- `apps-script.js`를 `vm`에 넣고, `SpreadsheetApp`·`CacheService` 등 구글 API를
  `lib/mock-sheets.js`의 목으로 갈아끼운다.
- `index.html`을 읽어 인라인 스크립트와 `src/` 파일들을 **문서 순서대로, 파일마다 따로**
  허용적인 DOM 스텁 위에서 실행한다(`lib/front-sandbox.js`). 파일을 이어 붙이지 않는 이유는
  브라우저처럼 "함수 호이스팅은 파일을 넘지 않는다"는 차이를 그대로 재현하기 위해서다.
- 마크업·CSS와 코드를 한 문서에서 대조하는 정적 검사는 `readFrontSource()`를 쓴다 —
  `src/` 태그 자리에 파일 내용을 끼워 넣은, 예전 단일 HTML과 같은 모양의 문서를 돌려준다.
- `save-path.test.js`는 위 둘을 동시에 띄우고 `_gasWrite`만 직결로 이어, HTTP만 생략한 채
  프론트→서버→응답 병합을 실제 코드로 돌린다.

`lib/real-headers.js`는 운영 시트 2행 헤더의 **실제 값**이다(`?debug=1`의 `columnError` 덤프에서
그대로 옮김). 추측이 아니므로, 시트 헤더가 실제로 바뀔 때만 고칠 것.

## 스위트

| 파일 | 지키는 것 |
|---|---|
| `columns.test.js` | 열 위치를 2행 헤더 텍스트에서 찾는다. 같은 텍스트가 두 열에 있는 `비고`(적립금 자리 / 신규 자유입력), 레거시 중복 `구성`·`목표수량`, `선착순` vs `선착순 수량`, `등급(수동)` vs `매출등급`이 서로 안 섞이는지. 헤더가 없으면 실제 헤더 행을 실은 에러를 던지는지. 열이 또 밀려도 코드 수정 없이 따라가는지. |
| `write-paths.test.js` | 등록·수정·실적 입력·팔로워 갱신·등급 초기화·릴스 저장이 **올바른 열**에 들어가는지. 공통 필드는 그룹 전 행에, 대표행 전용 필드는 대표행에만. |
| `frontend.test.js` | 서버 응답 → 공구건 객체 변환, 채널 단위 등급 산정, 시트 기록 payload 생성. 값이 같으면 요청을 아예 안 보내는지, 실패해도 화면에 영향이 없는지. |
| `save-path.test.js` | 저장 클릭 시점에 이미 화면이 새 값이고 요청은 1회만 나가는지. 총매출 **수식이 값으로 덮이지 않는지**. 실패 시 완전히 롤백되고 입력값은 남는지. 등급을 안 보낸 요청이 시트 G·H를 건드리지 않는지. |

## profile-save.js

테스트가 아니라 측정 도구다. Apps Script 지연은 거의 전부 "Sheets API 왕복 개수와 읽는 셀 수"에
비례하므로, 벽시계 대신 그 둘을 센다. 실제 스프레드시트 없이 운영 규모(370행×56열)를 재현한다.

출력의 `개선전` 열은 2026-09-15 최적화 이전 코드(커밋 `9b48305`)를 같은 도구로 잰 **기록된
실측값**이며 자동으로 재계산되지 않는다. 저장 구조를 또 바꾸면 그때 다시 재서 갱신할 것.

## 저장 경로를 건드릴 때 주의

- `_writeCellsBatched`는 **완전히 인접한 열**끼리만 한 범위로 묶는다. 떨어진 열을 묶으면 사이의
  총매출 수식이 값으로 박힌다 — `save-path.test.js`의 "총매출 수식 보존"이 그 방어선이다.
- `dealId → 행` 맵 캐시는 재사용 전에 전체 행 수와 후보 행의 dealId를 확인한다. 검증을 빼면
  사람이 시트에 행을 끼워 넣었을 때 **남의 행에 저장**된다.
- 저장 응답의 `tierRows`는 "시트 G·H가 지금 이렇다"는 뜻이다. 실제로 쓰지 않았으면 `null`이어야
  하며, 빈 문자열로 채우면 프론트가 불필요한 `writeTiers`를 한 번 더 쏜다.
